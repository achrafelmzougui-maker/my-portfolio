# Rapport de synthèse — Projets informatiques et systèmes intelligents

**Auteur:** Achraf El Mzougui  
**Formation:** Master ISI — Ingénierie des Systèmes Intelligents  
**Usage:** Portfolio / candidature de stage PFE  
**Date:** Novembre 2026

## Résumé
Le portfolio couvre développement web, apprentissage automatique, vision par ordinateur, systèmes experts et interfaces utilisateurs. Les projets se répartissent en code public vérifiable, prototypes nouvellement reconstruits et expériences historiques non accompagnées de leurs sources originales.

## 1. TrafficFlow AI
**Problème:** explorer les niveaux de congestion dans quatre zones de Kénitra.  
**Architecture:** frontend statique PWA, FastAPI, entraînement Random Forest, application mobile Expo prototype.  
**Données:** données artificielles; pas de flux temps réel, pas de validation sur le trafic réel.  
**Évaluation:** séparation temporelle et métriques prévues dans le pipeline; résultats chiffrés non certifiés ici.  
**Prochain jalon:** vérifier CI, déployer une API de démonstration et collecter des données autorisées.

## 2. Smart Attendance
**Problème:** simplifier la gestion de présence en classe.  
**Historique technique déclaré:** Python, OpenCV YuNet/SFace, SQLite.  
**Code public présent:** interface de démonstration avec élèves fictifs, suivi manuel et export CSV.  
**Limites:** le prototype web ne reconnaît pas de visages. Reconnaissance faciale ≠ preuve de présence; exigences de consentement, sécurité et supervision humaine.

## 3. Rasa Chatbot Scolarité
**Problème:** réponses automatiques à des questions scolaires courantes.  
**Code publié:** scaffold Rasa NLU, intentions, réponses, règles et scénarios de test.  
**Limites:** réponses administratives génériques, non vérifiées par un établissement; pas de modèle entraîné ou hébergé.

## 4. Football Value Predictor
**Problème:** illustrer l'estimation de la valeur de joueurs.  
**Code publié:** nouvelle démo Python kNN pondéré, jeu de données entièrement fictif.  
**Limites:** aucun prix réel; aucun indicateur d'erreur sur des données réelles.

## 5. Jeu de dames en Prolog
**Problème:** représenter les règles par des prédicats logiques.  
**Code publié:** démo de déplacement et capture simple en Prolog 8×8.  
**Limites:** pas de règles internationales complètes ni de moteur de partie.

## 6. Jeu éducatif arabe
**Projet historique déclaré:** application Java/JavaFX, Scene Builder et SQL.  
**Code publié:** nouvelle mini-démo HTML/JS de vocabulaire; ne remplace pas l'application originale.

## 7. Carte NFC
**Projet historique déclaré:** carte développeur numérique.  
**Code publié:** landing page responsive utilisable comme destination NFC/QR; aucun tag NFC programmé.

## 8. Projets historiques à documenter
**LV Manager:** plateforme de gestion pour agences de location de voitures, avec présentation et suivi client. Source originale absente.  
**La Sudvert:** gestion de stock VB.NET réalisée dans un contexte de stage; code non fourni.  
**E-commerce Bootstrap/PHP:** projet web historique; code non fourni.  
**Bibliothèque PDF:** moteur de bibliothèque / recherche; code non fourni.  
**Site de location de voitures:** projet Bootstrap/JS historique; code non fourni.

## 9. Compétences démontrées
Python, JavaScript, HTML/CSS, FastAPI, API REST, SQL, Prolog, principes de ML, tests, CI, documentation et interfaces responsive. Certaines compétences proviennent du parcours déclaré plutôt que d'un code actuellement visible.

## 10. Méthodologie de publication
Chaque projet doit préciser: objectif, architecture, prérequis, exécution, jeux de données, tests, captures, limites, licence des ressources et perspectives. Ne jamais publier données clients, secrets, photos d'étudiants ou code employeur sans autorisation.

## Conclusion
Ce portfolio fournit une base publique crédible pour présenter les acquis et la progression. Il doit être complété avec les codes originaux disponibles, captures d'écran réelles, résultats d'évaluation et démonstrations testées.
